The accent rule

  • Orange is never text. It fills the one primary button per page, marks the current sidebar item, draws focus rings, and borders accent chips.
  • Links are --text with a --border-strong underline that turns --accent on hover and focus.

Type scale

  • Atkinson Hyperlegible Next 400 / 600 / 700 for the UI; JetBrains Mono 400 / 500 / 700 for headings, labels, chips, ids and code.
  • Uppercase mono only for short chrome (section names, labels, chips). Never for ticket titles, questions or other prose. 11 px is the floor.
  • Pixels throughout; page zoom covers resizing.

3 Shell and layout

A left sidebar and a full-width main area. The project page stacks its header, its own Needs you list and the board. aisf runs on a laptop or PC, so there is no narrow layout.

From Prototype the app shell, navigation, layout and density (shell.html).

  • Sidebar (232 px, sticky, full height, --surface, --border-strong right edge): the aisf wordmark, Needs you with its total, a Projects label with one item per repo (mono repo name, owner/repo in the tooltip, its own count), + Add project, and Settings pinned to the bottom.
  • The current item gets --surface-2 and a 2 px accent inset on the left. Other items are muted and turn --text on hover.
  • Counts are square mono badges with --text numerals. The border takes the most severe member's colour: danger if anything is stuck, otherwise hitl. A zero count is not shown.
  • Main area: no width cap, 24 px gutter, 16 px rhythm. The project page is the header (repo name as a sentence-case h1, owner · checkout path in small mono, "Updated 3 min ago", and + New idea as the one primary button), then the project's Needs you list (hidden when empty), then the board.
  • Skills status shows only while it matters: a full-width banner above the main area while checking (● info) or blocked (■ danger with the fix). When it passes, nothing shows, and the details live in Settings.
  • Contract report shows nothing when it passes. When parts are missing, a warn panel above the board lists them in mono.

4 Status vocabulary

Every status is colour, shape and text together, never colour alone. One shape per colour family; the text tells statuses within a family apart. Orange is never a status.

From Decide the status vocabulary.

Family Colour Shape Statuses (lifecycle order)
Neutral, not started --muted ○ hollow circle idea, backlog
Flow, work moving --info ● filled circle; in-progress pulses (still under reduced motion) plan, planned, ready, in-progress, in-review
Waits for a human --hitl ● filled circle, no pulse waiting
Error --danger ■ square stuck
Warning --warn ▲ triangle conflict
Done --ok ✓ check closed (also closed as not planned, for now)
  • Chips: the label in --text, the shape in the status colour, a 1px border in the status colour, no fill, square. Shapes are aria-hidden; the text carries the meaning.
  • Names: written in sentence case with a space ("In progress"), shown uppercase via CSS in chips and row labels. Raw label names (status: ready) appear only where they are the point: the clashing labels on a conflict ticket.
  • Where: a board row label carries shape, name and count, and its cards carry no status chip. Everywhere a ticket appears outside its row (ticket page, Needs you, run transcripts, parent links) it gets a status chip.
  • The hitl flag means "runs as an interactive session": a chip with a purple border and no shape, because it is a flag, not a status. Purple means a human is in the loop: the HITL flag, hitl moments, and the waiting status. Waiting has a shape; the flag has none.
  • Needs you is not a status. It is a shell and list concern, marked by its reason: stuck shows red, a hitl moment shows purple.

5 Cards and board rows

A card is one link to the ticket page, stacked in three lines. Board rows wrap onto as many lines as they need.

From Prototype the card and list anatomy, links and collapsing (cards.html).

  • Card: at least 40 px, 8px 12px, --surface, 1px --border-strong, 4 px radius; the border turns --text on hover. Lines: #N (muted 12 px mono) and the title clamped to 2 lines with the full title in title; ↳ parent in small muted text on one line; a meta line with the conflict labels, HITL, "blocked by #N" (owner/name#N for another repo) and one PR #N chip per PR. Empty lines are left out.
  • The chips inside a card are inert spans without ↗. Their real links live on the ticket page.
  • Rows: the label row (shape, name, count), then cards in repeat(auto-fill, minmax(260px, 1fr)) with an 8 px gap. No cap and no sideways strip. An empty row keeps its label, a 0 and a muted "None". The Conflict row has a one-line note naming the fix.
  • Closed is a native <details>, collapsed by default, reading "50 of N" because the server loads only the newest 50, and ending with a link to all closed tickets on GitHub.

6 List rows

Every list is one bordered container of divided rows: a lead chip, a title with a sub-line, then metadata and the action. Lists are never capped.

From Prototype the card and list anatomy, links and collapsing. The row content is example text; each view's content is designed later.

  • Rows are separated by 1px --border hairlines and fill with --surface-2 on hover; 40 px minimum and 8px 12px padding, like cards.
  • Columns: a 112 px lead chip (reason, status or run state); the title on one line with an ellipsis and a small muted sub-line; muted mono tabular metadata (age, duration) and the action.
  • A row with an action stretches its title link over the row to the ticket page, and the action is a real button or link above it. A row without an action is one link.
  • A group header (a project on Needs you) is an 11 px mono uppercase band on --bg. Needs you sorts stuck first.

8 State patterns

Every surface covers loading, empty, error, stale and too much data the same way.

From Decide the state patterns and the copy voice, citing Research UI/UX guidelines for dense, readable tool UIs.

Loading

  • A static skeleton in the shape of the real layout. It appears after 300 ms and stays at least 500 ms. No shimmer: the pulsing in-progress mark is the only motion.
  • Board rows keep their real label with a count placeholder and 2 card blocks; lists show 3 divided rows; Closed shows one row of blocks inside its <details>.
  • aria-busy="true" on the region and a visually hidden role="status" text such as "Loading tickets…".

Empty

  • Text in place of the element, with at most one quiet action. No illustrations.
  • First use names the next step. Good news is one plain line with no action. Data that failed to load is never shown as empty; it uses the error pattern.

Errors

  • Say what happened, then the fix, in one or two sentences with no error codes. If no fix is known, say so. The raw server message goes on a muted second line.
  • Inline in place of what failed: the ■ danger mark with role="alert". Data that is still good stays up.
  • Banner for app-wide and project-wide conditions, full width at the top of the main area. Warn ▲ (role="status") when it recovers by itself; danger ■ (role="alert") when it needs you. Banners stack, most severe first. No toasts.
  • Polled data retries by itself and says when. One-off requests get a Retry button.

Stale

  • Always visible: a muted 13 px "Updated 3 min ago" on the right of each project page's header and on Needs you, as <time> with the absolute time in title.
  • When a poll fails or the watcher pauses, a warn banner gives the cause and the recovery without repeating the time. No dimming; counts stay, because they describe the snapshot shown.
  • Refreshes are not announced. This replaces the board design's earlier "Showing the board from HH:MM".

Too much data

  • Never cap on the client: board rows wrap without limit and every list row shows.
  • Where the server limits what it loads, say "50 of N" and link the full list on GitHub ↗ (Closed in section 5).
  • Card titles clamp at 2 lines with the full title in title; all other text wraps and is never cut. The page scrolls; no inner scroll boxes.

9 Copy voice

Plain and direct. Name who acted (aisf, GitHub, gh, the watcher). Fixes are imperative.

From Decide the state patterns and the copy voice.

  • No "we", "please", "sorry" or exclamation marks. Sentence case everywhere, except status names and 11 px mono labels, which go uppercase through CSS.
  • Numbers as digits with correct plurals ("1 part", "2 parts"). Buttons name the action ("Add project", "Retry"), never "OK" or "Continue".
  • Time: relative under 24 h ("just now", "3 min ago", "2 h ago", "in 20 min"), ticking once a minute; from 24 h on, local 24-hour "27 Sep 14:32", with the year only when it isn't the current one. Every time is <time datetime> with the full timestamp in title. Durations read "3 min" or "2 h 5 min".
  • Commands: a runnable command is a block on its own line after a sentence ending "Run:" or "Run, then Retry:". Mono on --surface-sunken, 4 px radius, no $ prompt, one command per block, and a Copy button that reads "Copied" for 2 s (announced via role="status"). Names in prose (a label, a path, a branch) stay inline <code> without a copy button.

10 Still open

Not decided by this direction. Each is left for later work on the map or the views that need it.

  • Notifications: browser notifications for hitl moments, and how they fit the shell (toasts are ruled out for errors).
  • Live updates: how a card that moved rows, or a new ticket, is signalled after a poll.
  • Keyboard and focus: navigation between sidebar, rows and cards. Today each card or row is one tab stop, plus its action.
  • Closed as not planned: shows ✓ for now; its own mark needs the watcher to read GitHub's stateReason.
  • Icons: whether the app uses an icon set. Status shapes are drawn in CSS or inline SVG either way.

Out of scope here: per-view designs (the ticket page, Needs you content, run transcripts, Known bugs, settings), small-screen layouts, and the aisf:design tool.
