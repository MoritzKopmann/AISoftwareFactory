Board and ticket page

The read-only board of a project's tickets and the ticket page stub it links to, in every state the app can put them in. Built on the UI direction and on the view models from #102; the component tickets for #68 are split from this page.

Sources: #68 Dev Notes (behaviour), docs/design/ui-direction.html (layout, density, status vocabulary, state patterns, copy), and kit.css as merged in #115 (tokens, fonts). No new token and no new font.

For review: where this follows the direction over the older plan

  • Sidebar instead of tabs. The direction puts projects in a left sidebar, so project-tabs.tsx becomes the sidebar. It shows only what the app backs today: the aisf wordmark, Projects, and + Add project. Needs you, counts, Settings and + New idea wait for their features.
  • Rows wrap; no sideways strip. #103 asks for "a long row that scrolls sideways"; the direction replaced it. Variant 7 shows a long row wrapping.
  • Stale board: "Updated 20 min ago" in the header plus a warn banner, instead of "Showing the board from HH:MM".
  • Loading: a skeleton in the shape of the board with a hidden "Loading tickets…" status, instead of a visible loading line.
  • Copy follows section 9 of the direction. The view models from #102 need their strings updated (listed under 12), which the board component ticket carries.

1 Full board

The project tab after a good poll. One row per status in lifecycle order, Idea first, Closed collapsed at the end. The row label carries shape, name and count, so cards carry no status chip. An empty row keeps its label, a 0 and "None".

  • Header: repo name as a sentence-case h1 (22 UI 700), owner · checkout path in small mono, and "Updated 3 min ago" on the right as <time> with the absolute time in title, from sync.checkedAt. It ticks once a minute.
  • Page padding 16px 24px 24px, 24 px between header and board, 12 px between rows, 6 px from a row's label to its cards, 8 px between cards.
  • In progress pulses its ● (1.6 s); nothing else moves. The poll refreshes silently every 5 s.

3 A failed sync with a stale board

The poll answers sync: failed with the last good board, or the request itself fails. A banner at the top of the main area names the cause and the recovery; the board below stays as it was, not dimmed, with its counts. "Updated" now reads from sync.snapshotTakenAt, so it shows how old the board is. The poll keeps going every 5 s and the banner goes away on the first good answer.

  • Warn ▲ (role="status") when it recovers by itself: rate limit, GitHub not answering, the app unreachable, the project not watched yet. Danger ■ (role="alert") when it needs you: gh not logged in, an unexpected error.
  • Banner: 10px 24px, --surface, 1px --border-strong bottom edge, a 4 px inset stripe in the status colour. The raw server message goes on a muted mono second line. No Retry button: polled data retries by itself.

4 Closed, expanded

Closed is a native <details>, collapsed by default, so a poll never re-collapses it. The server loads the newest 50, so the count reads "50 of N" and the row ends with a link to all closed issues on GitHub. When N ≤ 50 the count is just N and the last line reads "All closed on GitHub ↗" alone.

  • Summary: chevron › (rotates 90° when open, 0.15 s), ✓ in --ok, the label, the count, and "Show closed" / "Hide closed" as small muted underlined text. The whole summary is the click target.

6 Cards

One <a> to the ticket page (#/projects/<id>/tickets/<n>), one tab stop. Three lines, each left out when empty.

  • Box: min 40 px tall, 8px 12px, --surface, 1px --border-strong, 4 px radius, 2 px gap between lines. Hover turns the border --text; focus is the 2 px accent ring with a 2 px offset.
  • Line 1: #N (12 mono 500, muted, 6 px right) then the title (15/1.3), clamped to 2 lines with the full title in the card's title.
  • Line 2: ↳ parent title, 13 muted, one line with an ellipsis.
  • Line 3 (4 px above, wraps, 4px 8px gaps, 13 muted), in this order: conflict labels, HITL chip (--hitl border), "blocked by #N" per open blocker ("blocked by owner/name#N" for another repo), one PR #N chip per closing PR.
  • Chips are inert <span>s, no ↗: a link inside the card link is invalid. The PR links live on the ticket page.

10 Ticket page stub

#/projects/<id>/tickets/<n>. Fetched once, never polled. The sidebar keeps the project highlighted. Outside its board row a ticket carries a status chip.

  • Back: "← Back to the board", 13 px, a plain href to #/projects/<id>. The browser's Back works too.
  • Head: #N (20 mono 500, muted) and the title (22 UI 700, sentence case, wraps, never clamped). Below it, 8 px down: the status chip (shape in the status colour, pulsing for In progress) and "Open on GitHub ↗" (new tab, 13 px).
  • Facts: a <dl>, 112 px label column, 10px 16px gaps, a hairline above, max 720 px wide. Parent links in-app to its ticket page; a ticket without a parent leaves the row out. Pull requests link to GitHub (↗, new tab) with their state in small muted text; none reads "None".
